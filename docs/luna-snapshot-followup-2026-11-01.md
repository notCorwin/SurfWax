# 快照 frame 归属与 Token 复测

## 改动

- 子 frame 的文档插入其 iframe 行之后，并按实际语义层级缩进；未表示的 owner 会被标记，子文档仍保留。
- 默认快照省略逐行重复的、由角色推导出的操作提示；`fields` 仍可显式请求 `actions`。工具说明集中保留推导规则。
- 对子 frame 的占位提示，先证明本 frame 内文字和各级父 frame 宿主的完整包含，再输出原文；无法证明时标记未知。DOMSnapshot 的扁平树用于识别 open、closed 和嵌套 slot，不能仅凭页面 JS 的 `assignedSlot` 判断 closed shadow root。

## 验证

104 个单元测试文件、1490 项测试通过，构建、类型和工具文档检查通过。Chrome 155 扩展测试覆盖同源和跨源 frame、两层嵌套、同名诱饵、frame 替换、父级裁剪、open/closed slot 裁剪及分页。包含证明不检查其他元素遮挡，前后两次相同的证据也不能排除中间的 ABA 变化；普通系统字体等未能证明的提示仍可能为未知。

对之前真实 sequence 样本的 21 页快照，用 `o200k_base` 仅移除固定操作提示，完整 JSON 从 29,502 降至 27,024 tokens，减少 2,478（8.40%）。这是对旧样本的离线变换，未计入集中说明增加的提示词，也不代表实际计费或其他网页的普遍效果。

## 编辑区与预格式文本

后续快照对可操作的 `contenteditable` 宿主保留原有语义角色，并显示实际的富文本或纯文本编辑模式；可见但被 AX 隐藏的编辑区通过 DOM 补充。能力使用活体判定并在采集前后复查，同时识别 CSS `-webkit-user-modify` 的只读及模式覆盖；`designMode` 文档不把文档节点当成可调用的元素。对符合条件且未经过裁剪投影的 `pre`、`pre-wrap` 和 `break-spaces` 文本，保留已输出内容中的空格和换行。`pre-line` 和无法确认的预格式文本仍沿用原有空白规范化，不能宣称覆盖所有空白格式。

行 ID 的来源段由 `:ax:` / `:dom:` 缩为 `:a:` / `:d:`，保留 frame 范围及节点身份。对上一轮真实样本的 31 份快照进行离线替换，JSON 从 38,502 降至 37,324 个 `o200k_base` tokens，减少 1,178（3.06%）；工具上下文新增了少量引用用法说明，该离线数值不代表完整请求或实际计费的节省。数组行格式在同一样本上有更大潜力，但会影响现有动作回执及压缩容量校准，未直接接入。

最终源码通过 106 个单元测试文件、1524 项测试、构建与工具文档检查，以及 6 项 Chrome 回归；另有先前版本的分页与语义差分 Chrome 回归通过。一个明确要求使用 frame 引用的独立真实模型探针通过：模型使用此前快照中 Next iframe 的短引用，工具终态成功，fixture 记录一次正确的可信点击。该探针使用本地 `gpt-6-luna`、seed 17，耗时约 101 秒；这是定向提示下的单次样本，并非自由任务成功率。报告位于本地 `.dev/verification/frame-ref-probe/reports/1793540938958-17-7f216eff-6847-44ed-ab70-be5a8fd272bc.json`。

动作工具尚有独立边界：`contenteditable=true` 被 CSS `-webkit-user-modify:read-only` 覆盖时，现有 `fill` 的可编辑判定没有检查该样式；Chrome 实验中直接插入文本没有产生更改。本次只修正快照中的能力提示，动作工具行为需另行修复和验证。

## ARIA 补充、pre-line 与紧凑 ID

后续快照会补充页面可见但被 AX 隐藏的交互 ARIA 控件，保留已验证的 checked、expanded 等状态及可见文字。`aria-labelledby` 关联由浏览器解析并在采集期间复查；只输出已证实可见的关联文本，无法确认完整名称时标记未知且不绑定引用。重复 IDREF 按浏览器的实际顺序保留。`pre-line` 的常见内部空格、Tab 和换行现在分别按浏览器折叠；边界空白、CR/FF、投影及其他不确定情况仍保守处理。预格式证据复用 DOM 补充已有的布局遍历。

当前行 ID 使用 `<scope>.a<node>`、`<scope>.d<backend>` 和 `<scope>.m`；frame 范围及来源类型仍然独立。在上文相同的 31 份历史快照中，仅离线替换行 ID 后，JSON 从 37,324 降到 34,844 个 `o200k_base` tokens，减少 2,480（6.64%）；这不是实际请求或计费的测量。

本轮 106 个单元测试文件、1542 项测试、构建及文档检查通过，9 项 Chrome 回归通过，包括两个动态差分种子、重复标签引用、frame 替换和 `pre-line`。单次 `gpt-6-luna`、seed 17 的真实模型动态重排任务在 300 秒后超时，分类为 unknown：快照确认前三项已完成，模型随后定位了第四项但未在截止前完成任务。日志中一次请求出现 19 次上游重试；不能据此单独确定超时原因。首次 inspect 只返回 255 条中的 24 条，已完成工具调用携带的快照均被截断；模型未请求分页续取或 `since` 差分，操作使用元素 ref，因此这次也不能证明模型使用了短行 ID。报告记录日志不完整，不能据此证明完整操作账本。原始报告位于本地 `.dev/verification/snapshot-semantic-model/reports/1793543089134-17-9b620361-d036-426d-9cc8-742e8784b4e9.json`。

## 长行后的非权威前瞻

当完整快照的首个分页因超长行达到字节预算，且后面有可容纳的短行时，首包保留该长行的至少 512 个 UTF-16 单元，并在 `lookahead` 中附带部分后续完整行。这些行是稀疏、非权威的导航提示，可能缺少祖先上下文，不携带元素 ref，也不推进基线。原始快照及 UTF-16 游标仍保留，必须继续 `nextCursor` 才能完整重组；动作可用明确的角色和名称定位。`truncation.used` 仍统计主 `items`，而 `truncation.withLookahead` 统计 JSON `{items,lookahead}` 的 UTF-8 字节数且受同一预算约束。大结果转为 artifact 时提供单独的 `lookaheadAccess`。显式 `limit`、差分、续页及无法提供有用短行的情况保留原有行为。

这是改善有限首屏中的导航信息，不是无损压缩：后续完整遍历会再次返回前瞻中的行，因此总 Token 可能上升。全量 107 个单元测试文件、1554 项测试、构建和文档检查通过；6 项 Chrome 回归通过，覆盖预算、前瞻后的操作与完整游标重组、差分、同名及跨域 frame 归属。

固定源码和开发扩展，以 `gpt-6-luna`、seed 17 再次运行 300 秒动态重排任务：结果超时、`classification=unknown`，业务和交互验证均为 false，开发扩展和评测源码稳定性检查通过。模型首次 `inspect_page` 显式指定 `limit:100`，所以前瞻没有触发；与旧样本一样，首包为 255 行中的 24 行、主 `items` 为 11,999 字节，未显示 Next。后续自动快照出现包含 Next 的前瞻；模型继续通过 `find_elements` 搜索 Next 并点击 ref，5 次点击均报告成功，快照依次显示完成 1 至 5 项，但日志不完整，不能据此证明完整操作账本。模型行为也可能来自固定搜索策略，不能证明模型依赖前瞻或任务成功、Token 节省。新旧样本分别记录 21 和 11 个模型步骤、累计输入 947,525 和 496,436 tokens；轨迹不同，不能归因为这次改动。报告位于本地 `.dev/verification/snapshot-lookahead-model/reports/1793545115768-17-90c254d3-01e5-4b69-b184-99f303db0ac5.json`，未随仓库提交。

两次样本首次在 frame 内执行 `find_elements` 时的自动快照，同为 12,000 字节预算和 1280×720 视口：旧版 24 条主项、无 Next，完整快照 JSON 12,490 字节、按 `o200k_base` 为 5,143 tokens；新版 24 条主项及 119 条非权威前瞻（包含一个 Next），12,493 字节、3,930 tokens，约减少 23.6%。两次搜索本身都返回了带 ref 的 Next，因此不能证明模型依赖前瞻。Token 为离线编码估算，快照来自不同模型轨迹，不能外推为整体请求或计费节省。

## 显式行数限制与 artifact 提示

首个完整快照因预算在长行中截断时，现在即使指定 `limit`，也可预览其原始前 `limit` 行内的后续短行；主项和预览合计不超过该限制，冻结游标仍能恢复全部原文。对转为 artifact 的分页，输出增加了读取全部 items 后再继续或重建基线的提示；`baselineComplete` 只表示服务端按顺序生成了分页，不表示模型已经读取这些页。

单次固定源码的 `gpt-6-luna`、seed 17、300 秒动态重排复测仍超时、分类 unknown，源码及扩展稳定性检查通过。首次 inspect 未指定 `limit`，因此不能作为显式 `limit` 修复的模型对照；该次首包有 24 个主项和 95 个预览，其中包含一个 Next。模型随后尝试用预览中的完整名称点击，未指定 frame 而失败，再通过 frame 内搜索获得 ref 并成功点击。日志中的 7 次成功点击后快照依次显示完成 1 至 7/12，最终账本不完整，不能证明整关成功或比较任务效率。首次快照完整 JSON 为 12,518 字节、离线 `o200k_base` 估算 3,882 tokens；上一样本首次请求显式设置了 `limit:100`，12,534 字节、5,119 tokens，参数和模型轨迹不同，不能归因于本次改动。报告位于本地 `.dev/verification/snapshot-limit-model/reports/1793545779583-17-5c2a5bc5-ae0d-4f53-b267-5d78e610f748.json`。

该模型又一次跳过了已提示读取的 artifact，直接继续分页，因此提示并不能保证基线已送达。根本修复需要在确定模型可直接读取的结果大小后再提交分页进度，或对 artifact 的完整读取建立可验证的确认；当前不应将 `baselineComplete` 视作模型已重建基线的证明。另经 Chrome 截图实验，AX 隐藏的原生 progress/meter 可能有可见图形，但 CSS 遮挡、低透明度、伪元素和同色填充均可使 DOM 数值与实际可辨认像素不一致；当前快照无法保证覆盖所有此类绘制，不能把该数值直接当作可见文字输出。

## 显式快照页直送与分页租约

`inspect_page` 现在以完整工具响应（含 evidenceId）的 UTF-8 JSON 不超过 16 KiB 为上限，在同一冻结源上自适应调整主项预算；用户的 budget 仍是上限，`truncation.budget` 报告本页实际采用的上限。有效页直接内联，不能转成 artifact 后仍暴露下一页游标；如果不可截断的 URL、标题或其他元数据使页无法直送，返回明确的 snapshot-unavailable，不推进该观察的分页。它没有压缩长行：完整重组仍可能消耗较多 Token。

页面先准备，再通过内部租约验证快照身份并占用其分页位置；终态日志写入成功后才推进，失败则释放而不推进。并发竞争、重复和乱序读取、记录或 frame 失效均有针对性测试：失效时后续 cursor/since 明确 stale，不能生成基于不完整页的差分。终态写入只证明页进入了工具结果，不证明模型实际理解、保留或重建了它。

固定源码和开发扩展的单次 `gpt-6-luna`、seed 17 动态重排复测在 300 秒超时，分类 unknown；源码和扩展稳定性检查通过，日志不完整。模型有一次请求 `budget=30000`、`limit=256` 的续页，实际页上限为 15,843 字节，工具结果 16,383 字节且主项内联，无 artifact；该页是长名称的一个后续片段。模型没有继续读取余页，也没有请求 since，因此此样本不证明完整基线或差分。日志中的 5 次成功点击后快照依次显示完成 1–5/12。两次模型轨迹和参数不同，不能据此归因或比较总 Token。报告位于本地 `.dev/verification/snapshot-wire-model/reports/1793546902098-17-51d50a1a-bc95-4e89-b08f-17b49899daff.json`。

上述直送上限和租约目前只覆盖显式 `inspect_page`，不覆盖动作后的自动 pageSnapshot 或刷新消息。刷新消息在持久化前采集，且其 URL/标题超过 2,048 字节时会截断并标记；因此刷新路径仍不保证无损。异常巨大的显式快照元数据目前明确失败，也尚不能分页读取。

本轮完整单测以 10 秒默认测试时限运行，108 个文件、1565 项通过；构建和工具文档检查通过。3 项 Chrome 回归通过，包括大预算分页直接交付、完整 Unicode 重组、差分还原和前瞻；其中交付测试额外校验含 evidenceId 的实际响应不超过 16 KiB。
