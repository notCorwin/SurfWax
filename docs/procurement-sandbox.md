# 无模型采购审批沙盒

采购审批沙盒是一个本地网页任务，使用真实浏览器中的扩展及固定的工具调用序列验证操作通路。它不调用 LLM，也不需要 API 密钥。页面和业务服务运行在本机，扩展加载在隔离的 Chrome 配置中。

## 任务

采购门户的发票队列位于跨源 iframe 内。队列将十六条种子洗牌后的发票分成八页，并重复使用同两行 DOM；列表只显示编号、地区和状态，金额及 hold 状态需要打开详情并等待异步加载。任务要求遍历所有页，仅审批同时符合以下条件的发票：状态为 pending、地区为 APAC、金额不超过 $500，且没有 hold。审批时必须选择 `Approve`、理由 `Within policy`，并填写 `Approved under APAC policy`。其余发票必须保持原状。

数据包含金额等于 500 的边界值，以及金额超限、hold、已支付和地区不符的干扰项。不同种子改变记录顺序。此场景将分页、复用节点、跨源框架、异步详情读取、条件筛选和多字段提交放在同一条工作流中。

## 评分

业务状态和每一次提交尝试保存在测试进程中的服务端账本。判分要求每个符合条件的编号恰好成功提交一次，且没有错误或重复提交；最终符合条件的发票必须为 approved，其他发票不得变为 approved。服务端还检查提交时的版本、决定、理由和备注；无效或过期的尝试即使后来被修正也会使评分失败。测试检查业务结果时不以助手声称成功为依据。

## 结果的含义

固定响应替代模型选择工具，测试覆盖真实扩展和浏览器执行工具到网页状态变化的通路，不能衡量模型理解任务、自主规划或处理未知网页的能力。沙盒是确定性的本地应用，不代表真实网站的全部复杂性；未校准任务难度或模型成功率。账本能验证服务端收到的结果和提交历史，但页面接口也可被直接请求，因此账本本身不能证明所有读取和提交均经过用户界面，也不是防对抗的隔离。工具执行记录和测试脚本应与账本一起查看。

## 运行

在项目根目录安装依赖并构建扩展后，运行无模型集成测试：

```sh
npm ci
npm run build
npx playwright test e2e/procurement-tools.spec.ts --retries=0
```

测试使用两组种子，驱动扩展通过跨源框架逐页检查并提交六条符合条件的发票，同时核对独立账本和工具调用生命周期。Playwright 报告保存在 `playwright-report/`；失败时保留 trace 和截图。需要覆盖其他 Chrome 可执行文件时，可设置 `SURFWAX_CHROME_PATH`。
